# Verification and benchmark protocol

## Correctness

`go test -race ./...` covers randomized model comparisons, overwrite/delete precedence, scans, flush/compaction/reopen, value ownership, simultaneous callers, exclusive directory locks, torn WAL tails, replay after publication but before WAL retirement, record and manifest corruption, Bloom/index lookups, cache eviction, upload failure, and an AWS SDK HTTP Range round trip against a local protocol fixture. The fixture is not a full S3 emulator.

`make crash` starts the test binary in a fresh directory for each cycle. The child acknowledges unique-key writes over stdout only after `Put` succeeds. It repeatedly flushes and compacts. The parent chooses a seeded random acknowledgement count and short delay, sends SIGKILL, reopens the directory, and checks every observed acknowledged key. Writes that were durable but not observed over the pipe are permitted. CI runs 1,000 cycles on Linux; the committed transcript records a local run. This is sampled process-crash testing, not exhaustive fault injection or a power-loss test.

`make fuzz` exercises the framed-record parser with generated bytes. The default corpus also includes a valid frame and an empty input. CI runs a short smoke fuzz session, not an exhaustive campaign.

## Workloads

`benchmarks/run.sh` builds one benchmark binary and runs each workload in a fresh temporary directory for both StrataDB and bbolt. Both use one operation per transaction and match the synchronization setting. The driver checks returned values. Dependencies are pinned in `go.sum`.

| Workload | Operations |
|---|---|
| A | 50% reads / 50% updates |
| B | 95% reads / 5% updates |
| C | 100% reads |
| W | 100% new inserts |

These are YCSB-inspired mixes, not the official YCSB harness. Keys are sampled uniformly with seed 2027; there is no Zipf skew. Defaults: 2,000 preloaded keys, 5,000 measured operations, 256-byte values, one client, and a 256 KiB StrataDB memtable. Preload and its flush precede the timer. Automatic threshold flushes during operations are timed; the final explicit flush is not. No compaction runs during these benchmarks. This deliberately exposes L0 read amplification.

- **Throughput:** operations / timed loop wall duration, including driver overhead.
- **p50/p99:** sorted per-operation wall latency; includes automatic flush stalls but excludes preload and final flush.
- **Write amplification:** StrataDB's cumulative WAL + SSTable bytes divided by submitted key/value bytes, **including preload and final flush**. Excludes metadata, filesystem journaling, device-level amplification, and failed I/O. Not reported for bbolt because its physical writes are not instrumented here.
- **Space amplification:** sum of logical file sizes after final flush / current live key/value bytes. Includes WAL, manifest, lock file, and bbolt's logical database size. This is not allocated filesystem blocks or RSS.
- **Counters:** cumulative since open, including preload, not persisted. `BloomSkips` combines range rejections and filter rejections; it is not a false-positive-rate measurement.

The Bloom unit test separately checks 10,000 inserted even-numbered keys and 9,999 absent interleaved odd-numbered keys. At 10 bits/key and seven probes, the ideal independent-hash false-positive probability is `(1 - exp(-7/10))^7 ≈ 0.82%`; actual structured-key behavior is measured separately.

Results are a small, warm-cache local sample. There are no repeated-trial confidence intervals, multi-client saturation results, real S3 latency claims, or production-scale conclusions. bbolt is a mature comparison baseline; winning a tiny workload is not evidence of broad superiority.

## Reproduce

```sh
make check
make crash
./benchmarks/run.sh benchmarks/results.jsonl
python3 benchmarks/plot.py
python3 benchmarks/report.py
```

Plotting needs Python 3 and matplotlib. The engine and benchmark CLI do not need Python. Record the machine, OS, toolchain, and background load when collecting a new sample. Avoid running the crash harness and benchmarks at the same time.

## Check published evidence without rerunning workloads

Run `make evidence` to validate the full engine/mode/workload matrix, check
latency and derived metrics, test failure-safe result publication, and confirm
that the README tables match the raw JSON. This target uses Python's standard
library and Bash; it does not need matplotlib, AWS, or a database workload run.

The benchmark runner writes temporary result files and publishes them only after
all 16 configurations succeed. A failed run preserves the preceding results.
The results file and environment file are replaced separately, so a process crash
between those two renames can still leave mismatched files; rerun the suite if
publication was interrupted. Keep the pair together when archiving a run.
