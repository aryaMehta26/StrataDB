# S3 and local MinIO

The adapter uses AWS SDK for Go v2, its default credential chain, `PutObject`, and exact `GetObject` byte ranges. See the official [endpoint configuration](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-endpoints.html) and [GetObject API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html).

## Local setup

```sh
docker compose up -d
```

Open http://localhost:9001, sign in with the development-only username `stratadb-local` and password `stratadb-local-password`, and create a bucket named `stratadb`. Then:

```sh
export AWS_ACCESS_KEY_ID=stratadb-local
export AWS_SECRET_ACCESS_KEY=stratadb-local-password
export AWS_REGION=us-east-1
go run ./cmd/stratadb-demo -dir ./demo-data -bucket stratadb -endpoint http://localhost:9000
```

The demo uploads a compacted table, closes and reopens the database, reads a remote block, and repeats the read to show a cache hit. The local directory remains necessary: it contains the manifest, WAL, and lock. S3 objects alone are not a database backup. The bucket and prefix must be configured consistently on reopen.

## AWS

Use your normal AWS profile or role and an existing bucket:

```sh
AWS_PROFILE=your-profile AWS_REGION=us-east-1 \
  go run ./cmd/stratadb-demo -dir ./aws-demo-data -bucket your-bucket
```

Use a dedicated prefix with `s3:PutObject` and `s3:GetObject` permissions. Bucket creation is an operator step. Use the bucket's encryption and access policies; no credentials belong in this repository. The library creates immutable random object names beneath the configured prefix and never deletes remote objects. Repeated demos therefore leave objects behind; remove the dedicated test prefix when done. Real S3 requests and storage can incur charges.

The committed tests exercise the real SDK against an HTTP fixture and the engine against a failure-injecting in-memory object store. Live MinIO/AWS validation and hot-versus-cold latency measurements remain unverified in this initial release.
